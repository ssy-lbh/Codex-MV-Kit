# 资产生成与身份一致性

Sprite MV 的质量常取决于“使用什么 cel”，而不是增加多少缩放、旋转或闪光。先确定整身图的身份和姿态，再写动作；图像生成结果始终需要逐张审查。

## 角色资产最小集

| 资产 | 用途 | 验收重点 |
| --- | --- | --- |
| identity/reference | 固定角色身份的基准 | 头身比、发型、服装、关键色、左右不对称元素 |
| whole-body poses | 可切换的真实姿势 | 完整身体、紧凑自然手型、肩胯透视、接地关系 |
| expressions | 表演变化 | 目标表情明确，非目标身份区域未漂移 |
| background planes | 背景与前景分层 | 同画幅、透明边缘、遮挡关系和独立可组合性 |
| cover/title layout | 封面与文字布局 | 精确边距、区域占比、文字正确且来源可用 |

先做一位角色的一套小样，再扩展到另一位角色及全歌。不能因为单张正面图满意，就默认侧身、背身和动作图已经保持同一身份。

## 使用图片生成工具

若当前宿主提供内置 image generation / image edit，优先使用该能力并遵循它的输入要求。不同宿主和账号可能没有同样工具；不要写死工具名或宣称自动可用。工具不可用时，将提示词、参考图清单和预期输出路径保存到本地，提供手工导入流程。不要擅自安装云 SDK、索要 API key 或开启收费 API 作业。

对每次调用：

1. 确定参考图是用户提供或允许使用的素材，记录其来源和哈希。
2. 先检查实际参考图，避免向工具提交与文字描述不符的身份。
3. 指定透明背景、整身、留白和输出画幅；仅在任务确实需要透明时要求透明。
4. 将原始生成结果保存到本地，再做裁切、抠图、缩放或命名。不要只保留聊天预览链接。
5. 保存提示词、输入引用、工具/模型标识（若可得）、生成时间、输出哈希及后处理记录；未知值写 `null`。

可复用提示见 [prompts](../prompts/README.md)。模板描述的是目标，不是模型保证。

## 整身姿势与手型

要求画出完整姿势 cel：头、躯干、骨盆、双臂、双手、腿、鞋服共同服从同一姿态和视角。转身应改变肩宽、脸部朝向、胯部、前后腿与衣服遮挡。仅做正面图横向缩放、镜像或挪动手臂不能产生真实转身。

为手型写可见任务，例如“肘部靠近躯干，双手在胸前交握，指尖不伸出轮廓外侧”，比笼统要求“完美手”更容易审查。紧凑手型仍需核对手指数、腕部连接与左右手关系。避免让手遮住脸或重要服装标记，除非镜头明确需要。

保留相同画布、脚底基线与角色中心参考；实际姿态允许外轮廓改变。对齐时采用统一等比缩放，不把头、腿分别缩放来强行匹配边界。记录每个 cel 的锚点，避免切换时漂浮或脚滑。

## 表情编辑的边界

“仅修改眼睛与嘴，其他像素完全不变”可以表达意图，但生成式编辑可能改变头发、线条、颜色或 alpha 边缘。必须做非目标区域差分；提示遵从不等于像素相等。

如果需要严格固定身体，可由创作者选定批准的头部/脸部 mask，用本地确定性图像操作合成生成结果，并检查接缝。保留原图、编辑图、mask 和成图；不要把全图重生成描述成局部无损编辑。修图完成后还要用实际输出尺寸检查细线和透明边缘。

## 背景、FX 与线稿

背景按远景、中景、前景独立交付；所有层使用同一镜头和画幅。角色 sprite 不能同时带完整场景或被烘焙进背景。需要角色前后穿行时，明确定义可遮挡的前景层。

粒子、光束和光晕另建透明层；不要把人物变形藏在强光中。当前 `white_outline` 使用白色轮廓和黑色实体内部，保留完整身体 alpha 参与遮挡，再整体变换；它适合相应的黑底线稿视觉，不会自动生成保留所有内部细节的精细线稿。扩展其他线稿视觉时，也必须用相同变换处理可见图与 occluder。仅保留轮廓线的稀疏 alpha 会让后方角色从身体内部漏出来。FX 应显式限定对象和时间，字幕、背景和另一位角色不应被误处理。复杂粒子与光照的实际支持范围以 renderer 为准。

## Provenance 示例

下面是 sidecar 格式建议，不是 `project.json` schema。写入 `provenance/angela-pose-01.json`，将示意值替换为实际内容。不得用空哈希假装已验证。

```json
{
  "schema_version": 1,
  "asset_id": "angela_pose_01",
  "output_path": "assets/characters/angela/pose-01.png",
  "sha256": null,
  "origin": "generated",
  "source_url": null,
  "reference_assets": [],
  "prompt_path": "provenance/angela-pose-01.prompt.txt",
  "provider": "host_builtin_if_available",
  "model": null,
  "generated_at_utc": null,
  "license": "UNVERIFIED",
  "rights_notes": "Review provider terms and reference rights before redistribution.",
  "postprocessing": [],
  "review": {
    "identity": "pending",
    "whole_body_pose": "pending",
    "hands": "pending",
    "alpha_edges": "pending"
  }
}
```

资产哈希要在最终字节保存后计算；后处理改变文件就更新哈希。给 `assets` 中的每个引用保留真实许可摘要，详细信息放 sidecar。不要将“由 AI 生成”自动等同于 CC0、无权利负担或可公开所有参考图。

## 来源、credit 与封面

音乐、歌词、字体、插画、参考视频分别列来源与公开范围，注明是否只允许成片、是否可再分发源文件。封面精确排版可先生成无文字图，再用本地文字排版，减少错字；使用有授权字体。不要在公开模板中放受版权保护的歌词示例。用 `[授权文本]` 占位或自己写的测试短句。
