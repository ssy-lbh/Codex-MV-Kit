# 将已有 MV 经验迁移到通用项目

迁移目标是把可复用规则、可验证时间和可移动工程提取出来。不要将某个成片的角色、美术、音乐、字体、歌词、私人日志和历史版本原样复制进公共 toolkit。

## 先审查，再改写

保留旧工程只读副本，列清真正的入口脚本、最新输出、所用资产和配置。文件名里带“final”不能证明它是最终版本；比较输入哈希、渲染设置和已完成的人工审片记录。没有证据的状态标成未知。

首先完成源码审查。找硬编码绝对路径、全局变量、时间偏移、镜像代替姿势、逐片段重启循环、字幕二次烘焙、全视频 preload、末帧截断和尾部音频截短等行为。通读和小样复现比单纯复制配置更可靠。

## 迁移映射

| 旧工程常见状态 | 通用表达 |
| --- | --- |
| 多份带日期脚本 | 单一入口、版本控制、项目配置 |
| 机器绝对路径 | 项目内相对路径与稳定 asset ID |
| 每个裁剪片段局部从零动作 | 单一 global clock，保存 epoch/shift |
| 用调色时刻代表歌词起点 | source、vocal、display、FX 独立事件 |
| 只记录截图请求时间 | 记录实际 native PTS、帧索引和选帧策略 |
| 水平翻转正面图充当转身 | 独立真实整身 pose cel，人工审片 |
| 仅有线条 alpha 的遮挡 | 完整身体 alpha，与可见层相同变换 |
| 整片 RGB preload | 默认 12 帧的有界缓存与顺序解码 |
| `-t` 作为唯一长度控制 | `ceil(duration*fps)` 整数帧，再核对末帧 |
| 音频仅比较最短共同长度 | 全部声明窗口比较并报告尾部差异 |
| 复制整个文件夹称作备份 | manifest、ZIP、哈希与新目录实际恢复 |

## 推荐顺序

1. **列来源与权限。** 每个资产建立来源记录；未知许可不公开。公共 demo 重建为程序图形、程序音频和原创测试文字。
2. **提取全局时间。** 写清 BPM 候选、phase、epoch、已知锚点与容差。保留半拍/双拍歧义，避免过早定稿。
3. **迁移一个代表片段。** 选择 2–5 秒且包含切换/重叠的片段。核对同一 global time 下的 cel、位置、字幕和 FX。
4. **整理角色 cels。** 修正靠拼接、局部拉伸或镜像伪造的动作。每张整身姿势单独审核后才进入项目。
5. **映射到当前 schema。** 只有已支持字段进入 `project.json`；复杂 rig、原生 PTS 表或高级 FX 保存为 sidecar/扩展设计，不能让未知字段静默承诺效果。
6. **扩大到整片。** 检查整数帧、音频全窗口、字幕和首末帧，完整播放交付文件。
7. **恢复演练。** 在新的空目录恢复，重新校验和渲染代表片段。确认工程不再依赖原机器路径。

## 公共代码与私人作品分开

可公开的内容包括通用 renderer、校验器、timing 模型、synthetic fixtures、匿名化经验总结和提示词模板。私人作品的真实帧、音乐、歌词、角色图、商业字体、输出视频、绝对路径、聊天记录和日志属于另一个项目，不能因“用于解释”自动进入 Git。

即使仅发布源代码，也要检查错误信息、默认路径、测试 fixture、文档截图与文件名是否泄漏来源。Git 历史和当前文件树分别检查；删掉当前文件不会自动清除已公开历史。如果发现历史混入媒体，先停止公开并与仓库所有者确认处理范围，不要擅自 force-push。

## 迁移完成标准

在干净目录仅凭公开代码与新项目授权素材，可以 validate、渲染短片、完成 QA 并恢复。时间锚点有证据，姿势已审查，未知项明示。迁移成功说明工程可复现，不等于某个来源 MV 被像素级复刻。
